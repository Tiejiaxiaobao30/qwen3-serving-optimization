# 第一个学习单元：先区分两种“快”

本项目边做边学；现在只需要这个概念，不要求先背完整推理八股。

同一个服务，1个人请求时每人很快；8个人同时请求时，每个人可能等得久一点，但服务一秒钟总共输出的字更多。

- **TTFT**：请求发出后，到第一个非空内容事件的时间。用户感觉是“多久开始回答”。我们的客户端按流式内容事件观测，不把HTTP响应头当第一个token。
- **总输出吞吐**：成功请求的实际输出token总数÷测量总时长。它描述整个服务，不是每个用户的速度。

本地mock只检查工具是否会正确计时；它不加载模型，不能证明GPU性能。正式模型由AutoDL实例运行。

看已有历史T4记录：C1总吞吐50.122 tok/s、平均TTFT70.372ms；C8总吞吐273.31 tok/s、平均TTFT322.78ms。这组小实验说明两种指标可以同时向相反方向变化，尚不能确定最优并发。

小检查：如果并发提高后总吞吐增加，但首token等待也增加，你能否直接说“每个用户回答都更快了”？请用自己的话说一句理由。

完成这个检查，再学习prefill/decode；之后用长短提示的真实实验解释二者。面试题会从本项目实际结论生成，当前不提前背整套。
